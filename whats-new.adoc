===== 自定义信息板的通知

自定义仪表板现在包含共享设置。您可以将控制面板设为私有或与您的团队共享。

默认情况下，新控制面板是私密的，只有您可以看到。您可以随时将控制面板设为公开，以便与 Workload Factory 帐户中的所有人共享。

每个控制面板卡都会显示"私人"或"公共"标签，因此您可以快速查看哪些控制面板是共享的。

==== AI 功能管理

您可以通过 Workload Factory 管理中的以下设置来控制整个组织对 AI 功能的访问。

* 使用 NetApp 托管的 Bedrock（推荐且默认启用，设有每月信用额度限制）

通过新的管理页面，您可以在一个地方管理这些设置。

AI功能包括Ask Me、自定义仪表板、规则生成器以及EMS、数据库日志和卷延迟的分析器。

[[eda-workloads]]
=== EDA 工作负载



==== 具有成本控制的 AI 延迟分析

作为 Workload Factory 管理员，您可以控制对整个组织的 AI 延迟分析的访问权限。

* *NetApp 托管 AI 积分*：如果您的管理员启用了此功能，您可以通过 NetApp 的托管 Amazon Bedrock 集成使用 AI 分析。无需额外设置。您的每月使用量受您分配的预算限制。如果您达到每月限额，AI 功能将被禁用，您将看到一条消息。
* *由管理员禁用*：如果您的管理员关闭了 AI 功能，则 AI 分析选项将变为灰色，您将看到该功能已关闭的消息。




==== 弹性吞吐量增加管理

现在，您可以从 EDA 概述页面管理一个或多个选定的 FSx for ONTAP 文件系统的吞吐量增加行为。

* *模式选择*：选择 *Automate* 或 *Recommend*。
* *批量更新*：选择一个或多个文件系统，并在一个操作中应用模式和参数更改。
* *更改吞吐量管理对话框*：使用对话框中的 EDA 默认值编辑吞吐量增加设置。
* *Advanced settings*：在可扩展的 *Advanced configuration* 部分中配置其他吞吐量决策参数。
* *表可见性*：Clusters 表中提供了一个新的*吞吐量管理*列，可以从列设置中启用。
* *顶卡配置*：上卡现在支持吞吐量增加模式配置，类似于 SSD 管理。


link:https://docs.netapp.com/us-en/workload-eda/task-use-overview-dashboard.html["了解如何使用概览信息板"^]。

==== 适用于所有 FSx for ONTAP 系统的全新架构良好的仪表板

现在，可以从 NetApp Workload Factory 中新的架构完善仪表板对 FSx for ONTAP 文件系统进行架构完善分析。新仪表板在一个位置集中显示跨帐户和区域的所有文件系统及其配置。当您从文件系统访问*架构完善*选项卡时，会出现弹出通知。在 Workload Factory 的左侧导航菜单中选择*架构完善*，即可访问新仪表板。

您仍然可以访问特定文件系统的良好架构分析，也可以通过 Storage 中的 *Well-architected* 菜单选项进行访问。



==== 新小部件已添加到存储仪表板

存储控制面板现在包括两个新的小部件，可帮助您了解如何使用存储空间并找到优化存储空间的方法。

* *Top discovered workloads* 显示标记服务在整个环境中找到的工作负载数据。查看置信度得分高于 80% 的工作负载，其中包括相关的 FSx 资源，例如卷和块设备。每个工作负载都显示其名称、资源数量、已调配容量和已用容量。按资源计数（默认值）、已调配容量或已用容量排序，以快速识别最大工作负载并了解存储使用模式。
* *AI 驱动的洞察与观察* 显示您托管资产的 AI 生成洞察。该小工具会在选定范围内查看您的资产数据，并突出显示关键领域的前三大发现，包括容量、性能、数据保护、复制、成本节约和存储趋势。


每个见解都包括摘要、详细调查结果和建议操作。展开见解以查看更多详细信息，并根据严重程度、性能改进和节省成本的机会排定问题的优先级。



==== 工作负载标记



===== AWS Systems Manager 集成，用于工作负载标记

工作负载标记服务现在可与 AWS Systems Manager 配合使用，为主机库存数据添加更多详细信息。Workload Factory 现在可以收集和处理 SSM 库存信息，以更好地识别和分类工作负载。AWS SSM 属性也包含在标记过程中，以提高工作负载发现的准确性。

精心设计的仪表板中的每个卷相关配置现在都包含资源表中的 *Workload* 列。此列显示 Workload Factory 与每个卷关联的工作负载。



==== 工作负载标记和人工智能功能

当管理员禁用 AI 功能时，不会标记工作负载。如果在 Workload Factory 帐户设置中关闭了 AI 功能，则标记服务将不会识别或分类存储资源上的工作负载。

link:https://docs.netapp.com/us-en/workload-setup-admin/manage-genai-features.html["了解 AI 管理"^]。



==== 探索节省快照计算改进

探索节省功能现在使用一致的快照容量计算，因此 FSx for ONTAP 节省估算可正确考虑额外的快照容量池要求。

link:https://docs.netapp.com/us-en/workload-fsx-ontap/explore-savings.html["了解如何在 Amazon Elastic Block Store、FSx for Windows File Server 和 Elastic File System 上为您的存储环境节省成本。"]



===== 将复制延迟数据导出到CSV

现在，您可以将复制延迟数据导出为 CSV 文件，以便在电子表格中分析数据并与他人共享。



==== S3 访问点事件

您现在可以按照设定的计划将 S3 访问点事件发送到 SNS 主题。每次更新都包含自上次更新以来发生的所有事件。

要设置 S3 事件的通知，link:https://docs.netapp.com/us-en/workload-fsx-ontap/edit-s3-access-points.html["编辑 S3 接入点"]并选择 *Journal table* 部分下的 *Send S3 events by SNS*。

[[eda-workloads]]
=== EDA 工作负载



==== 通过同步延迟、IOPS 和吞吐量图表增强延迟分析

延迟分析面板现在包括一个具有同步性能图表的*详细延迟分析*页面：

* *延迟图*：显示延迟如何随时间变化，以及超出限制时的阈值线和警报。
* *IOPS 图形*：显示每秒操作数，以及过去超出限制的阈值线和指示器。
* *吞吐量图*：显示数据传输速率（DataReadBytes 或 DataWriteBytes）。在筛选器中选择元数据时，吞吐量图表不显示任何数据。


所有图形都使用相同的时间线，并根据事件是读取还是写入自动显示正确的指标。

您可以调整视图，并将延迟峰值与 IOPS 和吞吐量的变化相关联。违规标记和悬停详细信息可帮助您查看超出阈值的时间，并查看检测到的违规行为的关键指标。

https://docs.netapp.com/us-en/workload-eda/task-analyze-latency-trends.html["了解如何使用多个图表分析延迟趋势"^]。



==== 设置延迟通知频率

现在，您可以选择接收延迟违规电子邮件通知的频率：

* *每天提醒我（推荐）*：当任何 FSx for ONTAP 文件系统出现新问题时，您将收到通知。


如果同一个文件系统在一天内出现多个延迟问题，您只会收到一封电子邮件。

在发送文件系统的延迟警报后，Workload Factory 等待 24 小时后再为该文件系统发送另一个警报。

* *任何延迟违规通知（每 20 分钟一次）*：检测到违规时收到通知，最多每 20 分钟一次。


默认情况下，每日通知处于启用状态，以减少电子邮件数量，同时仍提醒您注意延迟问题。您可以在设置延迟监控或编辑阈值设置时更改通知首选项。

https://docs.netapp.com/us-en/workload-eda/task-configure-latency-monitoring.html["了解如何配置延迟监控"^]。

link:https://docs.netapp.com/us-en/workload-fsx-ontap/set-volume-latency-thresholds.html["在 NetApp Workload Factory 中设置卷延迟阈值"]



==== 在 NetApp Workload Factory 中跟踪复制延迟

使用 NetApp Workload Factory，您可以跟踪配置了远程复制的 FSx for ONTAP 文件系统的复制延迟。复制延迟表示数据写入源文件系统和复制到目标文件系统之间的时间延迟。跟踪复制延迟可帮助您监控复制设置的运行状况，并确定可能影响数据一致性和恢复点目标 (RPO) 的潜在问题。

link:https://docs.netapp.com/us-en/workload-fsx-ontap/track-replication-delays.html["在 NetApp Workload Factory 中跟踪复制延迟"]



==== NetApp Workload Factory 中的主机标识和工作负载定义

Workload Factory 标识使用存储的主机以及与主机活动相关联的工作负载类型。工作负载定义是基于 AWS 标记和元数据的 AI 生成的。您可以从 Workload Factory 中的文件系统、卷和块设备资源屏幕查看主机详细信息和工作负载定义。



==== NetApp Workload Factory 中可用的 LIF 详细信息

我们直接在文件系统的"概述"选项卡中显示所有文件系统和存储虚拟机端点。Workload Factory 控制台内的直接端点可见性使您可以更轻松地监控网络访问、端点和故障转移状态，而无需使用 CLI 或 CloudShell。要显示 LIF 详细信息，包括角色、端点、节点、IP 地址和状态，您需要将链接与文件系统关联。

link:https://docs.netapp.com/us-en/workload-fsx-ontap/create-link.html["了解如何在 NetApp Workload Factory 中将链接与您的文件系统关联"]。



==== 成本增强功能

新的可选页面级筛选器可用于改进所有 AWS 账户的资源成本分析结果。您可以选择多个区域，并使用文件系统分配标记键和键值来过滤成本分析结果，并获取针对 FSx for ONTAP 文件系统和卷的资源特定成本详细信息。

link:https://docs.netapp.com/us-en/workload-fsx-ontap/track-costs.html["在 NetApp Workload Factory 中使用筛选器进行成本分析"]



==== NetApp Workload Factory 中提供复制初始化调度

在数据复制设置期间，您现在可以为 FSx for ONTAP 文件系统安排复制初始化。选项是立即或在指定时间初始化复制关系。复制初始化是通过将数据从源文件系统复制到目标文件系统来创建复制基线的过程。计划复制初始化允许您自动执行此过程，并确保您的复制设置为最新，而无需手动干预。

link:https://docs.netapp.com/us-en/workload-fsx-ontap/create-replication.html["在 NetApp Workload Factory 中复制数据"]

link:https://docs.netapp.com/us-en/workload-fsx-ontap/improve-configurations.html["在 NetApp Workload Factory 中查看 FSx for ONTAP 文件系统的良好架构状态"]



==== 查看和分析延迟事件

Workload Factory 现在支持查看和分析 FSx for ONTAP 卷的延迟事件。您可以在没有链接连接的情况下查看延迟事件，从而更轻松地监控性能问题。要分析延迟事件并接收基于 AI 的见解和建议，您必须使用链接连接到文件系统。分析提供当前延迟值、阈值、QoS 响应分析和补救指导。

link:https://docs.netapp.com/us-en/workload-fsx-ontap/analyze-events.html["在 NetApp Workload Factory 中分析 FSx for ONTAP 事件"]



==== 设置卷延迟阈值

现在，您可以按卷配置延迟阈值，以便在读取或写入延迟超过定义的限制时监控性能并接收警报。延迟监控可帮助您在影响工作负载之前主动识别性能问题。

link:https://docs.netapp.com/us-en/workload-fsx-ontap/set-volume-latency-thresholds.html["在 NetApp Workload Factory 中设置卷延迟阈值"]

==== SSD 容量增加管理模式和自动化

Workload Factory 现在提供 SSD 容量增加管理模式，以匹配您的操作偏好：

* *自动化*
* *推荐*
* *无*


当前模式及其参数显示在文件系统详细信息页面的 SSD 使用情况图表的顶端。您可以根据操作需求随时切换模式。

link:https://docs.netapp.com/us-en/workload-eda/task-use-overview-dashboard.html#change-ssd-management-mode["了解 SSD 管理模式"^]。



==== 批量编辑 SSD 容量增加管理参数

现在，您可以从概览仪表板调整多个文件系统的 SSD 容量增加管理参数。在群集表中选择一个或多个群集，并批量编辑阈值（10-90%）、回溯（1-200 小时）和提前（1-200 小时）值。

编辑对话框根据您的选择自动填充：如果所有选定的文件系统共享相同的参数值，则会显示这些值；否则，将使用默认值。这有助于您在整个环境中应用一致的容量设置。

link:https://docs.netapp.com/us-en/workload-eda/task-use-overview-dashboard.html#bulk-edit-ssd-management-parameters["了解如何批量编辑参数"^]。



==== 容量决策点可视化

SSD 使用情况图表现在显示决策点，指示何时生成容量建议或采取自动操作。

* *建议决定点*：悬停以查看时间戳、建议增加的大小和当前容量。
* *自动化决策点*：悬停以查看时间戳、成功或失败状态、增加大小和新的聚合大小。失败的尝试包括失败原因。


决策点可以每 30 分钟发生一次，并根据选定的时间范围单独显示或合并显示。

link:https://docs.netapp.com/us-en/workload-eda/task-use-overview-dashboard.html#analyze-capacity-trends-and-decision-points["了解容量决策点"^]。



==== Clusters 表中的链接配置状态

概览仪表板上的集群表现在包括一个关联链接列，该列显示是否为每个文件系统配置了 FSx for ONTAP 链接。连接状态每天验证，帮助您识别需要链接配置或可能存在连接问题的文件系统。

link:https://docs.netapp.com/us-en/workload-eda/task-use-overview-dashboard.html["查看概览仪表板"^]。
